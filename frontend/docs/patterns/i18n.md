# i18n

Two representations of "language" exist in this app and must never be conflated:

| | Values | Used for |
|---|---|---|
| svelte-i18n locale | `en-US`, `ru-RU` | `$locale`/`$t(...)` text lookups, `Intl`/`toLocaleDateString` calls, translation dictionary keys |
| URL lang | `en`, `ru` | Every route path (`/en/...`, `/ru/...`), every `goto()`/`href` build |

`core/i18n/url-lang.ts` is the single bridge module between them — `url_lang_to_locale`,
`locale_to_url_lang`, `is_supported_url_lang`, `detect_url_lang(navigator.language)`. Nothing
outside this file should hand-map between the two forms.

**Rule of thumb for a new `$locale`/`page.params.lang` usage:** if it's building a URL (`goto`,
`href`, an `isAtLocaleRoot` check), it must use `page.params.lang` (`$app/state`), not `$locale`.
If it's a text lookup, dictionary key, or anything passed to `Intl`/`toLocaleDateString`, it must
use `$locale`, not `page.params.lang`. Mixing these was the exact bug fixed in `Nav.svelte`,
`Card.svelte`, and `DicomUploadCard.svelte` — grep for `$locale` before adding a new URL-building
call site and check which category it falls into.

## Translation Dictionaries

`core/i18n/en-US.json` / `ru-RU.json`, flat-ish nested JSON, typed via `LocaleKey` in
`core/i18n/types.ts`. Any dictionary keyed by locale in application code (not the i18n files
themselves) must use the **full** `en-US`/`ru-RU` keys, never `en`/`ru` — a dictionary keyed
`en`/`ru` silently never matches `$locale` and falls back to whatever `fallbackLocale` is
(`en-US`), which reads as "translation just doesn't work for the other language" rather than an
obvious error. See `gotchas.md`.

## Setting the Locale

`set_locale(url_lang: UrlLang)` (`core/i18n/index.svelte.ts`) is the only way to change
`svelte-i18n`'s locale — it converts through `url_lang_to_locale` first. Called once, from
`routes/[lang]/+layout.svelte`, with `data.lang` (already validated as a real `UrlLang` by the
load function — see `routing.md`).

## Readiness Gate

`i18nState.i18nReady` (`core/i18n/index.svelte.ts`) flips true once `waitLocale()` resolves.
`routes/[lang]/+layout.svelte` gates all rendering on `i18nState.i18nReady && project.registry.ready`
— both async singletons must be ready before anything mounts, not just i18n.
