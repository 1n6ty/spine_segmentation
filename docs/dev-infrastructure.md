# Dev infrastructure

`dev/` is a self-contained, modular infra stack — one subfolder per service, each with its own `compose.yaml` — mirrored from the sibling project `lambumiz-plus`'s `dev/` folder. `dev/compose.yaml` stitches them together via Compose's `include:`, and the repo-root `compose.yaml` includes that in turn, so every service below is part of the same stack as `mainland`/`nginx`/etc.

**Deviation from lambumiz-plus**: there, `dev/` is dev-only — production runs against separately managed infra via a downstream deploy project. spine-segmentation has no such downstream project (CI/CD is out of scope for this work), so `dev/compose.yaml` is included by **both** `compose.dev.yaml` and `compose.prod.yaml` — production continues to self-host its own infra in containers, exactly as it did before this change, just with more pieces now.

## Why each piece exists

- **`dev/MySql/`** — the actual MySQL server. Stock `mysql:9.4.0` image (kept at the version already in use) with `init.sh` creating the app database/user and a read-only `proxysql_monitor` account.
- **`dev/ProxySql/`** — connection pooling in front of MySQL. The app (`mainland`/`mainland-celery`/`mainland-cron`) connects to `proxysql:6033`, never directly to `mysql:3306`. A reader host-group (42) is configured but unused today (no read replica exists yet) — it's there so adding one later doesn't require touching application config.
- **`dev/Redis/`** — three independent Redis instances (`redis-cache`, `redis-session`, `redis-broker`) instead of one shared instance with logical DB indices. Isolates Django's cache + WebSocket-presence keys, Django's sessions, and Celery's broker from each other — a problem in one (e.g. the broker filling up under task backlog) can't starve the others.
- **`dev/RedisProxy/`** — HAProxy in front of the three Redis instances, exposing them on fixed ports (6379/6380/6381) behind one hostname (`redis-proxy`), with health checks that specifically verify `role:master` on each backend. **Found during live verification**: HAProxy does *not* substitute `${REDIS_PASSWORD}` inside `tcp-check send` strings itself — the literal placeholder was sent verbatim, breaking the AUTH handshake and marking every backend down (`NOSRV` in the logs, every Redis connection from `mainland`/`mainland-celery` failing with "Connection closed by server"). Fixed the same way as ProxySQL's own template: render `haproxy.template.cfg` through `envsubst` at container start (to `/tmp/haproxy.cfg`, since `/usr/local/etc/haproxy/` isn't writable by the image's non-root `haproxy` user) before `haproxy -f` reads it.
- **`dev/MinIO/`** — S3-compatible object storage for the two media buckets (`media-public`, `media-private`). `minio-init` is a one-shot job that creates both buckets and sets `media-public` to a public-read policy.
- **`dev/MinIOProxy/`** — an nginx proxy in front of MinIO (`minio-proxy:9000` → `minio:9000`). This is **not** the same nginx as `backend/Nginx/` — this one is internal-only plumbing between the app/the main nginx and MinIO; see [build-and-deploy.md](build-and-deploy.md) and [backend-architecture.md](backend-architecture.md) for how `media-public`/`media-private` are actually served to a browser (nginx `proxy_pass` and X-Accel-Redirect, respectively — neither talks to MinIO directly).
- **`dev/Traefik/`** — the externally-facing HTTPS gateway, replacing what used to be nginx's own `listen 80`. Terminates TLS, redirects HTTP→HTTPS, and forwards everything to the main `nginx` service. MinIO is never routed through Traefik directly — only through the main nginx, same as every other request.

## Two things deliberately not copied from lambumiz-plus

1. **`settings.REDIS`/`settings.SYNC_REDIS`** — lambumiz-plus's `common/mixins/v1/ws_consumer.py` and `common/utils/ws_consumer.py` reference these, but no `Lmzplus/settings/*` file defines them — they don't exist there. It doesn't crash only because lambumiz-plus's `ws_urls.py` is empty (no consumer ever connects). spine-segmentation's are real, working `redis.asyncio.StrictRedis`/`redis.StrictRedis` clients (`Mainland/settings/modules/database.py`), pointed at the new `redis-cache` instance via `redis-proxy`.
2. **`manage.sh restore`** — documented in lambumiz-plus's `AGENTS.md`, accepted by its argument parser, but there's no actual `restore)` case in its script. Nothing to mirror — not added here.

## Credentials note

`proxysql_monitor` (MySQL) and ProxySQL's admin interface (`admin`/`adminpassword`) are hardcoded, internal-only accounts — not reachable outside the Docker network, not meant to be put in `.env`. Everything else (`DEFAULT_DB_NAME`, `DB_USER`, `DB_PASSWORD`, `MYSQL_ROOT_PASSWORD`, `REDIS_PASSWORD`, `MINIO_USER`, `MINIO_PASSWORD`) comes from the env file — see `example.env`.
